# Task: Implement delivery service (GUARANTEED vs BEST_EFFORT orchestration)

## Status: COMPLETED

## Summary
Implemented the delivery service with full GUARANTEED vs BEST_EFFORT orchestration semantics as specified in the PRD Task 7.

## Components Implemented

### 1. src/notification/policies.py
- `NotificationPolicy` data class for per-notification-type policy configuration
- `ModeOverride` for autonomy-mode-specific overrides
- `PolicyRegistry` for policy lookup with fallback to defaults
- Default delivery mode resolution (SAFETY/GOVERNANCE -> GUARANTEED, others -> BEST_EFFORT)
- Default channel routing per autonomy mode:
  - PREVIEW: All intents -> WebSocket only
  - SHADOW: OPERATIONAL -> WebSocket, GOVERNANCE -> Slack+WebSocket
  - LIVE: Intent-based defaults with PagerDuty for irreversible SAFETY
- Default ack requirement (SAFETY + LIVE -> true)
- Configurable ack timeouts and dedup windows

### 2. src/notification/deduplication.py
- `DeduplicationStore` abstract base class
- `InMemoryDeduplicationStore` for testing
- `RedisDeduplicationStore` for production (SETNX + TTL)
- `generate_dedup_key()` for stable key generation
- `DeduplicationEngine` for managing dedup state
- Global `should_deduplicate()` function as primary interface

### 3. src/notification/service.py
- `DeliveryService` - Main orchestration class implementing PRD strict step order:
  1. Deduplication check
  2. Rate limit check (per channel)
  3. WebSocket delivery (fire-and-forget)
  4. Persistent channel delivery:
     - GUARANTEED: Sequential fallback (Slack -> Email -> PagerDuty)
     - BEST_EFFORT: Concurrent delivery to all channels
  5. Ack timeout scheduling (if required)
  6. Audit log write
  7. GUARANTEED failure raises DeliveryError

- `DeliveryError` exception for GUARANTEED mode failures
- `SimpleAdapterRegistry` for adapter management
- Protocol interfaces: `AdapterRegistry`, `AuditLogger`, `AckScheduler`
- No-op implementations for testing

### Key Semantics Implemented:
- **GUARANTEED**: Must raise if all persistent channels fail, escalates via callback
- **BEST_EFFORT**: May fail silently, logs failure, returns FAILED status
